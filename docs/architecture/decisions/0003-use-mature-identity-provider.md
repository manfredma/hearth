# ADR-0003: 认证协议核心采用成熟身份提供商

- **状态**: Superseded by [ADR-0006](0006-self-hosted-oidc-provider.md)
- **日期**: 2026-09-22
- **决策者**: 项目所有者

## 上下文

认证中心需要处理密码、MFA、Session、Token、密钥轮换、统一退出、账号生命周期和审计。自行实现这些能力会扩大安全维护面，也无法仅靠业务测试覆盖协议边界。

## 原决策

Hearth 不自行实现 OIDC/OAuth 2.0 认证核心，优先评估并托管成熟身份提供商。Hearth 自己实现应用接入、用户映射、管理体验、审计和业务系统适配层。Keycloak 为首选评估对象，ZITADEL 保留为同等候选；最终产品选型另行记录。

放弃从零开发认证服务器，因为它会把协议安全、凭据保护和运维高可用都变成 Hearth 的长期核心负担。

## 后果

**正向**

- 复用标准协议和成熟生态。
- Hearth 的代码聚焦于统一身份目录和跨应用集成。
- 可替换底层身份提供商，降低业务系统直接绑定某一实现的风险。

**负向**

- Hearth 需要维护外部身份提供商的部署、升级、备份和监控。
- 身份提供商的能力边界可能限制部分定制需求。
- 需要维护 Hearth 与身份提供商之间的用户和应用同步契约。

## 假设

| 假设 | 可证伪信号（出现时重评） |
|------|--------------------------|
| 候选身份提供商支持 OIDC、OAuth 2.0、MFA 和环境隔离 | 关键需求只能通过修改身份提供商源码实现 |
| Hearth 的核心需求可通过标准 API 和事件集成 | 业务系统必须依赖某一厂商私有扩展才能运行 |

## 替代说明

项目所有者后来明确选择自建 Hearth 身份提供商，以便练习 OAuth/OIDC、保留定制能力并避免引入独立的第三方身份服务。新方案不从零实现密码学和协议细节，而是使用 Spring Authorization Server 作为 Hearth 进程内、可替换的协议内核；完整边界见 ADR-0006。

## 退出条件

| 信号 | 预设行动 |
|------|----------|
| 候选产品无法满足核心安全或生命周期要求 | 重新评估另一成熟产品；只有在完成安全评审后才考虑 Spring Authorization Server 等框架方案 |
