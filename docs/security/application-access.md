# 应用访问模型

应用访问是 Hearth 与业务系统之间的最小授权接口：用户先通过 OIDC 完成认证，再由 Hearth 判断是否允许进入某个已登记应用。应用内部的菜单、功能、对象和数据权限不在 Hearth 中实现。

`role_key` 采用应用命名空间，例如 `daylilt:editor` 或 `career:viewer`，用于向业务系统传递明确的能力提示；业务系统必须自行验证该提示是否仍有效，不能把它当作不可撤销的全局权限事实。

应用登记要求唯一 `application_key`、显式回调地址和环境隔离。生产与 staging 不共享 client、回调地址或应用访问数据。
